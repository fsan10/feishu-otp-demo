## 覆盖的主要行为

- 历史入口的应用发送者身份与事件入口的机器人发送者身份。
- 不需要 @ 的机器人消息；普通用户、其他群、其他机器人及错误账号内容被忽略。
- ID 类型精确匹配；不把事件 header 的接收 App ID 当作发送方。
- 同一消息跨两个入口重复出现时，只处理一次；已消费 ticket 不能再次领取。
- 等待窗口之前、未来时间、过期时间、已撤回或已修改的消息不用于提交验证码。
- 同一路由互斥；可区分店铺各取自己的验证码；重叠路由拒绝猜测。
- 文本、富文本、常见 1.0/2.0 卡片中的可读文字提取。
- 电话号码、日期、余额等数字不被默认规则误当成验证码；多验证码正文不选择某一个。
- 下载 worker 被消息接收线程唤醒；取消、超时及权限错误释放等待状态。
- token 缓存和刷新、历史分页、分页异常、频率限制重试、临时故障恢复及请求超时预算。
- 自定义机器人假短信正文格式及签名参数。

## 重现命令

在解压目录运行，使用你项目约定的 Python 3.12 解释器：

```bash
python3 -m otp_bridge demo
python3 -m pip install -r requirements-websocket.txt
python3 -m unittest discover -s tests -v
python3 -m compileall -q otp_bridge examples tests
```

没有安装官方 SDK 时，仅其兼容性测试会跳过；离线演示与轮询相关代码仍可使用。

本结果证明代码在模拟消息、模拟 HTTP 响应与实际 SDK 数据结构下的行为。实际群权限、短信转发模板、机器人白名单、原下载流程和同账号并发限制，需要按 `FEISHU_SETUP.md`、`AI_INTEGRATION.md` 做真实环境验收。
